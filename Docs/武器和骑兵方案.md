---

### 背景概述与核心原理

`VgCrowdLegion` 是基于 UE 5.8 官方实验插件 **AnimToTexture (A2T)** 的 **BoneAnimation** 模式扩展开发的海量军团渲染方案。
其核心思想是：**将传统 SkeletalMesh 的 CPU 骨骼蒙皮与动画采样，转为预烘焙的 VAT 贴图（骨骼位置 `BonePositionTexture`、旋转 `BoneRotationTexture`、蒙皮权重 `BoneWeightsTexture`），并在 GPU 顶点着色器（WPO）中完成变形，由 `HISM`（分层实例化静态网格）合并为一个 Draw Call 极速渲染。**

HISM 上的每个实例通过 **4 个 PerInstanceCustomData (PICD)** 浮点参数驱动动画：
- `CustomData[0]`: `TimeOffset`（相位偏移或单次时间补偿）
- `CustomData[1]`: `PlayRate`（复合速率：正数表示循环，负数表示单次定格）
- `CustomData[2]`: `StartFrame`（当前动作在全局 VAT 上的起始帧）
- `CustomData[3]`: `EndFrame`（当前动作在全局 VAT 上的结束帧，含）

### 一、击中情形如何处理？

在万人同屏的 HISM 架构下，网格体本质是静态网格实例，**没有 CPU 骨骼，也没有物理碰撞体/布娃娃（Ragdoll）**。因此击中处理采用**“分层分级处理”**策略：

#### 1. 集群轻受击 / 批量击退（GPU 纯动画单次播放）
当单位受到普通攻击或需要表现受击动作（Hit Reaction / Hurt / 僵直）时，系统完全在 GPU 动画层解决，保持零 CPU 蒙皮开销：
1. **自动识别单次动作：** 在 `CrowdLegionExporter::GenerateAnimMetaDataTable` 中，包含 `hit`、`hurt`、`cut`、`prick`、`attack`、`death` 等关键词的动作被自动判定为 `bDefaultLoop = false`。
2. **时间戳对齐与单次定格：**
   - 当调用 `CrowdUnitComponent::SetCellAnimByName(Index, "Hit")` 时：
     - `CD_TimeOffset` 被写入 `-GetCurrentAnimationTime(World)`（负的当前世界时间），使得材质中的 `(Time + TimeOffset)` 恰好从 0 开始。
     - `CD_PlayRate` 写入 `-Abs(PlayRate)`（负数作为单次标志）。
   - 在材质函数 `GetCrowdLegionFrame` 中：
     ```hlsl
     bLoop = Playrate >= 0;
     Offset = bLoop ? Floor(Fmod(Elapsed, Length)) : Min(Length - 1, Floor(Elapsed));
     Frame = StartFrame + Offset;
     ```
     当速率为负时，GPU 自动钳制在动画末帧（`Min(Length - 1, ...)`）。
3. **恢复 Idle：** 若为轻击，业务层在受击时长结束后将该 Cell 切回 `Idle`（重新写入正向速率与随机错落相位）。

#### 2. 重击击飞 / 击杀倒地 / 投石爆炸（HISM 实例 → 动态置换物理 Ragdoll）
在工程验证框架（如 `ARagDollCharacter` 与 `RagdollTestController`）中，真实的布娃娃物理交互采用**“动态置换机制（Dynamic Seamless Swapping）”**：
1. **命中判定与索引拾取：** 投石或攻击射线碰撞到 HISM，由 `FHitResult.Item` 获取到被击中的 `InstanceIndex`。
2. **无缝替换为真实 Actor：**
   - 从 HISM 取得该实例的世界坐标与旋转（`GetInstanceTransform`）。
   - 调用 `CrowdUnitComponent::RemoveCell(InstanceIndex)` 将该实例从群组渲染中移除（或缩放到 0 隐藏）。
   - 在该 Transform 处动态生成（`SpawnActor`）一个具备完整 Physics Asset 的 `ARagDollCharacter`。
3. **物理与冲量传递（NativeEnterRagdoll）：**
   - 开启全身体物理模拟：`SkeletalMesh->SetAllBodiesSimulatePhysics(true)`。
   - 在命中骨骼处施加真实冲量：`SkeletalMesh->AddImpulseToAllBodiesBelow(ImpulseDir * ImpulseMag, HitBoneName, true)`。
   - 触发残肢分离（Dismemberment / `SpawnSeveredLimb`）以及动态血迹贴花（`SpawnDecalAttached` 到最近骨骼）。
4. **性能闭环（回收机制）：**
   - 当物理 Actor 静止沉睡（Sleep）一段时间后，销毁该 Actor，或将其当前最终姿态转录回残骸 HISM，避免物理 Actor 常驻消耗 CPU。

### 二、骨骼插槽上挂武器，HISM 和 BoneAnimation 怎么处理？

#### 核心矛盾
- 传统 SkeletalMesh：武器是一个独立 StaticMesh/Actor，通过 `AttachToComponent` 绑定到骨骼插槽（如 `weapon_r` / `hand_r`），CPU 每帧计算插槽变换并驱动武器。
- **HISM + BoneAnimation：** HISM 只渲染静态网格，没有 CPU 骨架，也没有实时 Socket Transform，无法在运行时动态挂接子组件跟随。

#### `VgCrowdLegion` 的标准解决方案：预绑定多材质插槽（Pre-skinned Multi-slot Section）
在最新的 `2026-11-08-a2t-export-boneanimation-slots-design.md` 和 `CrowdLegionExporter` 规范中，彻底移除了旧有的 2x2 Atlas 贴图合并方案，采用**多材质插槽管线**：

1. **DCC/源网格阶段绑定：**
   - 武器不作为独立挂载物，而是在 SkeletalMesh 导出阶段就将武器网格合并入角色的源骨骼模型中，并将武器顶点 100% 赋权（Skinning）给手部骨骼（如 `weapon_r`）。武器使用独立的 Material Slot。
2. **导出 StaticMesh 时保留多插槽：**
   - `CrowdLegionExporter::ExportStaticMeshFromSkeletalMesh` 调用 `UAnimToTextureBPLibrary::ConvertSkeletalMeshToStaticMesh`，**保留原 SkeletalMesh 的所有材质插槽与原始 UV**（不破坏象限，不压缩到一个槽）。
   - 武器顶点与身体顶点作为同一个 StaticMesh 的不同 Section，顶点上的骨骼权重（Bone Weights）一并保留并烘焙进同一份 `TX_BoneWeight` 贴图。
3. **每槽独立生成 BoneAnimation 材质实例（MI）：**
   - 导出器遍历导出的静态网格材质槽，为身体槽、铠甲槽、武器槽分别生成：
     - `MI_<Character>_BoneAnimation_Body`
     - `MI_<Character>_BoneAnimation_Weapon`
   - 这些 MI 指向同一个父材质（如 `M_Archer_BoneAnimation`），**共用同一套骨骼动画贴图（`BonePositionTexture`、`BoneRotationTexture`、`BoneWeightsTexture`）**，仅 BaseColor/法线贴图覆盖为武器贴图。
4. **运行时效果：**
   - 角色和武器是**同一个 StaticMesh 实例**。
   - 顶点着色器执行 WPO 骨骼变换时，武器顶点根据自身的骨骼索引自动跟随手部骨骼挥舞。
   - **完全没有 CPU 插槽开销，武器与角色在同一个 Draw Call 内绘制完毕。**

*(注：若业务确实需要运行时频繁“动态卸下/更换武器”，则需走**“双 HISM 配对架构”**：单独建立 `WeaponHISM`，武器同样烘焙该骨架的 VAT，传入相同的 4 个 CustomData 参数在 GPU 端保持同频偏移。)*

### 三、骑兵有两个模型，马和角色同时播放动画怎么处理？

#### 核心矛盾
- 马（四足四肢骨架）与骑手（双足人形骨架）的**骨骼层级完全不同（Skeleton Hierarchy 不兼容）**，不可能合并进同一份 A2T 贴图烘焙。
- 两者必须是两个独立的 DataAsset、两套不同的 VAT 贴图、两个不同的 HISM。
- 必须保证两者在**空间位置上不脱节**、在**动画时间轴与相位上毫秒级锁死**。

#### `VgCrowdLegion` 的处理方案：双 HISM 镜像联动架构（Dual-HISM Linked Architecture）

```
                     ┌──────────────────────────────────────────────┐
                     │          Cavalry Legions Manager             │
                     │  - Maintain cavalry units (Unit Index i)    │
                     └──────────────┬───────────────────────────────┘
                                    │ 1:1 镜像同步
            ┌───────────────────────┴───────────────────────┐
            ▼                                               ▼
┌───────────────────────────────┐               ┌───────────────────────────────┐
│     HorseUnitComponent        │               │      RiderUnitComponent       │
│  - HISM (SM_Horse_A2T)        │               │  - HISM (SM_Rider_A2T)        │
│  - DA_Horse (马匹骨骼贴图)    │               │  - DA_Rider (骑手骨骼贴图)    │
│  - DT_Horse_AnimMeta          │               │  - DT_Rider_AnimMeta          │
└──────────────┬────────────────┘               └──────────────┬────────────────┘
               │                                               │
               │ Instance i                                    │ Instance i
               ▼                                               ▼
     CustomData[0..3]                                CustomData[0..3]
     (TimeOffset, PlayRate, Start, End)              (TimeOffset, PlayRate, Start, End)
               ▲                                               ▲
               └───────────────────────┬───────────────────────┘
                                同一时间戳 / 相同相位
```

#### 1. 空间对齐方案（Spatial Pinning）
- **DCC 制作层统一 Root（推荐标准做法）：**
  - 在制作动画序列时，马匹与骑手的绑定动画以**同一个世界原点（Ground Origin）**为参考系进行导出。
  - 骑手的 RefPose 骨骼在制作时就已经带有相对地面的高度偏移（坐在马背鞍座的相对高度）。
  - 在生成时，对于骑兵 `i`：
    `HorseTransform[i] == RiderTransform[i]`（两者的 World Transform 完全相同）。
  - 位移时，调用 `BatchMoveCells` 对马和骑手传入完全相同的 `MovementDelta`，两者在世界空间中完美重叠平移，无需在 CPU 运行任何复杂的局部空间矩阵变换。

#### 2. 成对动作状态机（Paired Animation State Table）
逻辑层定义骑兵的复合状态字典：
```cpp
struct FCavalryAnimationPair
{
    FName HorseAnimName;    // 如 "Horse_Run"
    FName RiderAnimName;    // 如 "Rider_Slash"
    bool  bLoop;
};
```

#### 3. 时间与相位绝对锁定（Phase & Time Synchronization）
GPU 动画是根据 `(View.RealTime + TimeOffset) * PlayRate` 进行采样的。如果不强制对齐时间，马和人会出现“马在狂奔、人在慢步”或脚步与身体起伏颠簸脱节：
- **循环动作（如跑步 Run）：**
  在切换动作时，生成一个共享的随机相位：
  ```cpp
  float SharedPhase = FMath::FRand() * 10.0f;
  // 同时赋给马匹和骑手实例的 Phase / TimeOffset
  HorseCellData[i].Phase = SharedPhase;
  RiderCellData[i].Phase = SharedPhase;
  ```
- **单次动作（如冲锋刺杀 / 落马 Death）：**
  获取同一时刻的高精度动画时间戳：
  ```cpp
  float SharedNow = GetCurrentAnimationTime(World);
  // 双方的 TimeOffset 均写入 -SharedNow，两边 GPU 采样从第 0 秒完全同步起跑
  HorseCellData[i].TimeOffset = -SharedNow;
  RiderCellData[i].TimeOffset = -SharedNow;
  ```
- **帧率与周期匹配（PlayRate Scaling）：**
  若马匹跑步循环为 0.8s，骑手动作长度为 1.0s，可通过比值调整骑手的 `PlayRate`：
  $$\text{PlayRate}_{\text{Rider}} = \text{PlayRate}_{\text{Horse}} \times \frac{\text{Duration}_{\text{Rider}}}{\text{Duration}_{\text{Horse}}}$$
  使两者在 GPU 端的单次循环耗时绝对一致，马背颠簸与骑手身形起伏完全咬合。

### 总结对照

| 维度 | 传统 SkeletalMesh 模式 | VgCrowdLegion (HISM + A2T) 模式 |
| :--- | :--- | :--- |
| **击中表现** | 动画蓝图切 Montage；致命伤开物理布娃娃 | 轻击：改写 PICD 单次速率在最后一帧 GPU 定格；<br>重击/击飞：**拔出实例，原地 Spawn 物理 Actor 施加冲量**。 |
| **骨骼插槽挂武器** | `AttachToComponent` 到 Socket，每帧 CPU 算 Transform | **源网格预蒙皮到手部骨骼，StaticMesh 保留多插槽**，武器共享 VAT 材质并由 GPU 顶点索引直接跟随。 |
| **骑兵多模型动画** | 角色挂到马的 `Saddle` 插槽，主从 Tick 传递骨骼位移 | **双 HISM 实例 1:1 镜像配对**，统一地面原点 Transform，**共享 `TimeOffset` 与 `PlayRate` 实现 GPU 采样强锁定**。 |

### 四、UCavalryUnitComponent 组件设计与使用

在 `VgCrowdLegion` 插件中已正式落地 `UCavalryUnitComponent : public UActorComponent`（位于 `VgCrowdLegion/Public/CavalryUnitComponent.h`），用于海量骑兵阵列的极速渲染与动作驱动。

#### 1. 核心架构
- **双 HISM 容器**：内部创建并维护 `HorseHISMCmp`（马匹）与 `RiderHISMCmp`（骑手）两个 `UHierarchicalInstancedStaticMeshComponent`。
- **实例 1:1 镜像配对**：实例索引 $i$ 强对齐，`HorseHISMCmp[i]` 与 `RiderHISMCmp[i]` 始终代表同一名骑兵。
- **双动画元数据表**：分别配置马匹的 `HorseAnimMetaDataTable` 与骑手的 `RiderAnimMetaDataTable`（`FUnitAnimationTableRow`）。

#### 2. Setup 阶段接口
```cpp
void SetupCavalryHISM(
    UStaticMesh* InHorseMesh,
    const TArray<UMaterialInterface*>& InHorseMaterials,
    UDataTable* InHorseAnimTable,
    UStaticMesh* InRiderMesh,
    const TArray<UMaterialInterface*>& InRiderMaterials,
    UDataTable* InRiderAnimTable,
    int32 PreallocateCount = 0);
```
若未传入材质数组，会自动从对应静态网格体的插槽材质自动填充。

#### 3. 实例与动画接口（对齐 UCrowdUnitComponent）
- `AddCell(Transform, AnimName, PlayRate, bLoop, StartTimeOffset)` / `AddCellByIndex(Transform, AnimIndex, PlayRate, bLoop, StartTimeOffset)`：马匹与骑手成对添加到相同 Transform。
- `BatchAddCells(Transforms, AnimIndex, PlayRate, bLoop)` / `BatchAddCellsByName(Transforms, AnimName, PlayRate, bLoop)`：批量压入双端 HISM 并仅标记一次渲染状态脏数据。
- `RemoveCell(Index)` / `ClearCells()`：双端同步移除与清空。
- `UpdateCellTransform(Index, Transform, bWorldSpace)`：双端同步更新。
- `BatchMoveCells(MovementDelta, bFaceMovementDirection, bTeleport)`：在 CPU `CellTransforms` 上整队平移/朝向后批量同步各 HISM 层；死亡单位由调用方先 `RemoveCell`。
- `SetCellAnim(CellIndex, NewAnimIndex, InPlayRate, bInLoop)` / `SetCellAnimByName(CellIndex, AnimName, InPlayRate, bInLoop)`：切换单个骑兵的动画并锁定共享相位。
- `SetAllCellsAnim(NewAnimIndex, InPlayRate, bInLoop)` / `SetAllCellsAnimByName(AnimName, InPlayRate, bInLoop)`：批量切换全部骑兵的动画状态，仅在结尾刷新一次双端渲染状态。

#### 4. 同名动作与相位锁定机制
调用 `SetCellAnimByName(CellIndex, "Run")` 或 `SetAllCellsAnimByName("Run")` 时：
1. **同名查找**：马匹与骑手分别在各自的动画元数据表中查找名为 `"Run"` 的动画片段并获取各自在 VAT 上的闭区间：
   - 马匹：`[HorseStartFrame, HorseEndFrame]`
   - 骑手：`[RiderStartFrame, RiderEndFrame]`
2. **绝对相位锁定**：
   - **循环动作**：生成同一个共享相位 `SharedPhase = FMath::FRand() * 10.0f`。
   - **单次动作**：使用相同的实时时间戳 `-GetCurrentCavalryTime(World)`。
   - 双方 CustomData[0] 统一写入 `SharedPhase`，CustomData[1] 统一写入带符号的 `SignedRate`。
3. **GPU 顶点变形**：马匹与骑手虽然骨骼数与 VAT 尺寸不同，但在着色器端使用相同的物理时间轴采样，动作与马背起伏毫秒级同步。
